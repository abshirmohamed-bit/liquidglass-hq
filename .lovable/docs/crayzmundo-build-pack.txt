Key differences from the AgencyAdmin rebuild (already handled in these prompts): 
This is an extension, not a rebuild. Every prompt says "add to the existing app"; the Client, Payment, TeamMember, ClientProgress, AnalyticsSnapshot, Ideation, Thumbnail, KnowledgeEntry, Lead, AppSetting and CrayoJob entities and the 20 existing backend functions stay. New entities are added, never recreated. Standalone by design. Every clipping, editing and rendering step runs on the crayZmundo Engine, a service you own: ffmpeg, Whisper, OpenCV and Claude in one Docker image on a $5–20/month host, with its API contract and its own build prompts in the Engine tab of this doc. Base44 talks to it through one backend function, engineClient . No vendorAPI is called anywhere: the tools Crayo and OpusClip sell (their clip finders, editors, caption styles, formats, posting and scheduling) are rebuilt natively across the prompts below, and the Parity tab lists each one with the prompt that builds it. The only outside services left are the ones that cannot be avoided: the social platforms' own posting APIs, one AI model API for judgement (Claude by default, swappable), and the host and storage bucket you rent. 
Secrets, not AppSetting. The first build stored API keys in the AppSetting entity, which any signed-in browser can read. Prompt 1 moves every key to Base44 Secrets and backend functions read them with Deno.env.get() ; nothing below works until that is done.

ENGINE API BASICS (use exactly these; the full contract is pasted at the end of this prompt): 
- Base URL: ENGINE_URL (AppSetting). Header Authorization: Bearer <ENGINE_API_KEY>. JSON bodies on POST and PATCH. Errors come back as { success:false, error:{ code, message } }. 
- Rate limits: 2 requests per second and 50 per minute by default; uploads 20 per minute; polling GETs 120 per minute. Every response carries RateLimit Remaining; on 429 wait the Retry-After seconds and retry once. - Uploads and imports cost nothing. GET /v1/account returns storage used and limit, the queue (jobs waiting, estimated wait) and which providers are configured (TTS, images, stock footage). 
BACKEND FUNCTION engineUpload (direct upload; video up to 4 GB in mp4, mov, webm, mkv, avi, m4v, mpg, wmv, flv, 3gp; audio up to 100 MB in mp3, m4a, wav, aac, ogg, flac; images up to 20 MB in jpg, png, webp, gif; fonts up to 5 MB in ttf, otf, woff2; subtitle files .srt and .vtt up to 2 MB): 
- action "start": takes filename, contentType, sizeBytes. Calls POST /v1/uploads with { filename, content_type, size_bytes } and returns the upload id, signed url, method and headers to the browser; creates a

Tips for a smooth build 
Go in order. Later prompts assume the entities, roles and functions from earlier ones exist. Prompt 1 before anything else: the key leak is the reason nothing else is safe to ship. 
Build each one fully before the next. If Base44 stops mid-build, say "continue". After each build, do the "Check before moving on" step; a broken webhook in Prompt 3 will look like a broken review grid in Prompt 4. 
Two tracks, one contract. The Base44 prompts (this tab) and the Engine prompts (the Engine tab) can be built in parallel because both follow the same API contract. Deploy the Engine scaffold first (Engine Prompts 1 and 2 are an afternoon's work) and run it with ENGINE_MOCK=true: every endpoint then answers with fixture clips and fake progress, so Prompts 2 to 7 here can be built and tested before the heavy pipeline exists. Turn mock mode off once Engine Prompt 5 is done; nothing in the app changes.
